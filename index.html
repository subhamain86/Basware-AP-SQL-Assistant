Welcome — what does this tool do?

AP-SQL Assistant · Version 11.1 — This assistant writes database queries for you — both read-only reports and Change Request SQL — using your organization's approved database schema as its single source of truth. New in V11.1: a full UI rectification pass (alignment, spacing, and responsive behavior across every screen size and zoom level), a clearly labeled Schema Synchronization Schedule in the navbar, and a proper schema lifecycle — every stored schema can now be marked Active or Inactive, with exactly one Default schema, manageable from Used Schema (quick toggle) and Update Schema (full admin configuration).

Select Default Schema New in V11.1

Choose exactly one stored schema as the Default. The Default schema is always Active, and is the schema that Live Shared Schema, linked-file sync, and GitHub sync update automatically. Changing the default does not remove any other schema from the active selection.

Select Active Schemas New in V11.1

Tick any number of stored schemas to make them Active app-wide; untick to make them Inactive (kept safely in storage, just not used for SQL generation, the Query Builders, or the Error Rectifier). The Default schema is always included and cannot be deselected here. Nothing is deleted by deactivating a schema.

Manage Stored Schemas New in V10.7

Add a brand-new named schema, or choose an existing one below as the target for uploading, downloading, or deleting content — this is independent of Default/Active status above.

Live Shared Schema Zero Setup for Everyone Else

Makes the Default schema available automatically on every device and browser. On every page load, the app checks a well-known path relative to this page.

Cross-Device Schema Sync (Administrator) Option A

Link the Default schema to a single shared file (SharePoint, OneDrive, or a network drive). Requires a Chromium-based browser.

GitHub-Hosted Schema Sync (Administrator) Option B

Connect with your repository details and a Personal Access Token. This connection can now be saved to an encrypted vault below, so any authorized user can restore it on any machine without re-typing the token.

Your Personal Access Token is stored only in this browser's local storage and sent only to api.github.com over HTTPS. Use a fine-grained token scoped only to this one repository with Contents: Read and write permission.

Secure GitHub Connection Vault New in V10.7

Encrypt the GitHub connection above (owner, repository, branch, path, and token) with a passphrase, and publish it to the project repository as an encrypted vault file, so any authorized user on any machine can unlock the exact same connection just by knowing the passphrase — without ever seeing or re-typing the token.

Please note: this is a browser-only application with no server. The vault is genuinely encrypted (AES-256-GCM), and the token is never stored or shown in plain text anywhere — but because this app has no server-side secret store, the passphrase itself (never stored alongside the vault) is the real access boundary and must be shared with authorized users separately, exactly like the operational password below.

Fill in the Owner / Repo / Branch / File Path fields above before unlocking — a Personal Access Token is only needed here if the repository is private; public repositories can be read anonymously.
